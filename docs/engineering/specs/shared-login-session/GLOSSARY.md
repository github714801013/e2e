# 共享登录会话术语

本词汇表区分三种会话：单次 run 内的测试会话、同一次 HTTP MCP Run 内的认证快照、以及跨 run 的共享登录会话。三者的生命周期与作用域不同，不能混用。

## 术语

**共享登录会话（Shared login session）**：target 声明的一份登录，由账号、登录钩子和校验钩子描述；框架在每个测试开始时恢复它的缓存状态，状态失效时重新登录。作用域是 target，不是单个测试，也不是单次 run。
_避免_：Run 会话、认证快照、测试会话。

**共享会话状态（Shared session state）**：登录成功后由引擎捕获、供后续测试恢复的引擎状态；它只描述“已登录”这一事实，不包含账号密码。
_避免_：cookie 文件、认证快照、凭据。

**登录声明（Login declaration）**：`target.session` 的 `{ account, login, check }` 三件套；`login` 执行登录，`check` 判断当前状态是否仍然有效。
_避免_：测试脚本内的登录步骤、setup 测试。

**账号（Account）**：`config.credentials` 中的一个具名条目，提供用户名与不透明密码句柄；共享会话状态按账号隔离。
_避免_：用户、凭据值、环境变量名。

**凭据句柄（Credential handle）**：框架交给登录钩子和校验钩子的账号句柄；密码是 opaque `Secret`，只能经框架授权的填充动作使用。
_避免_：明文密码、`Secret` 的值。

**存储键（Store key）**：由站点身份、环境与账号派生的稳定摘要，决定共享会话状态的归属；run 分配的端口与 target 名不参与。
_避免_：runId、target 名、端口。

**冷启动（Cold start）**：没有可用共享会话状态时执行一次登录并保存新状态的过程。文件缺失、身份不匹配、解密或校验失败，以及二次确认后校验仍失败，都属于冷启动。
_避免_：首次运行、缓存未命中（后者只表示文件缺失）。

**二次确认（Re-confirmation）**：抢到登录锁后重新加载并恢复共享会话状态、再执行一次校验的步骤；仍无效才登录，避免并发重复登录。
_避免_：重试登录、重新登录。

**登录锁（Login lock）**：跨进程独占的 advisory 锁，只保护登录与重登动作；持有者崩溃后按固定 stale 时间接管。
_避免_：共享会话锁、文件锁（泛指）。

**测试会话（Test session）**：现有 `test.setup` 产出、由 `{ session }` 消费、只在单次 run 内有效的命名会话。显式使用测试会话的测试不注入共享登录。
_避免_：共享登录会话、认证快照。

**sharedSession 选项**：测试选项，默认开启。设为 `false` 时该测试不恢复共享登录，用于测试登录流程本身。
_避免_：`session` 选项、关闭 target 的登录声明。
